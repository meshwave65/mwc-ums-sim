Security Boundary

Segurança: Auth primeiro, RLS sempre

CamadaRegra recomendadaPor que importa
Chave no clienteSomente publishable / anon; nunca service_role.A chave pública identifica o projeto; a autorização vem da sessão e das policies.
Postgres RLSExigir auth.uid() e filtrar por usuário/owner nas tabelas.Evita que um usuário leia ou escreva dados de outro, mesmo conhecendo a API.
Storage policiesPermitir INSERT/UPDATE somente no prefixo do usuário autenticado.O caminho do objeto vira uma fronteira de isolamento, não apenas uma convenção.
ObservabilidadeMapear erros 401 / 403 / RLS para estados explícitos da UI.“Pendente” e “confirmado” não podem ser confundidos em uma fila assíncrona.
